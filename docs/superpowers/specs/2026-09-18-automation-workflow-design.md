# 自动登录与定时抢课工作流设计

## 范围

在现有本地 FastAPI Web 控制台中增加完整自动化工作流：安全保存账号凭据、自动验证码登录、当前轮次跟随、搜索与高级目标、互斥分组和会话保活。继续支持现有六个模块；本期不实现钉钉通知。

## 安全边界

- `config.json` 位于项目根目录，首次启动时自动生成，权限设置为 `0600`。
- 配置文件保存学号，不保存密码、Cookie、登录票据或验证码。
- 密码以服务名 `qfnu-course-web`、账户名为学号保存到 macOS 钥匙串，通过系统 `security` 命令读写。
- Web API 不返回密码。浏览器只在保存密码时提交一次，且不写入浏览器存储。
- 日志不记录密码、Cookie、OCR 图片、登录票据或完整 Webhook。当前版本没有 Webhook 配置。

## 配置结构

```json
{
  "version": 1,
  "account": {
    "username": ""
  },
  "auth": {
    "ocr_url": null,
    "ocr_attempts": 3,
    "keepalive_seconds": 300
  },
  "selection": {
    "round_keywords": [],
    "start_time": null,
    "requests_per_second": 5.0,
    "poll_interval_seconds": 0.1,
    "max_runtime_minutes": null,
    "term_id": null
  },
  "targets": []
}
```

- `selection` 字段为兼容旧配置保留。服务端始终归一化为空轮次关键字、立即启动、每秒 5 次请求、0.1 秒扫描间隔、无最长运行时间且无学期 ID。
- 所有配置由 Pydantic 严格校验，未知字段和不支持的版本会被拒绝。
- Web 页面编辑后点击“保存设置”写入文件。程序启动时自动加载配置和目标。
- 现有 YAML 导入导出保留，用于课程目标迁移；`config.json` 是自动化配置的权威来源。

## 登录流程

教务文档没有独立 CAS 端点。程序按已记录流程执行：

1. 初始化教务会话并获取验证码图片。
2. 使用随控制台启动的内置 `ddddocr` 模型识别验证码图片。
3. 获取 `scode`、`sxh`，编码学号和钥匙串中的密码。
4. 提交 LDAP 登录，并仅跟随同源 SSO 重定向。
5. 访问学生主页确认登录状态。

内置 OCR 在应用启动阶段加载一次，识别工作在线程中执行，避免阻塞 Web 事件循环。自动登录最多按 `ocr_attempts` 重试验证码。OCR 初始化失败、识别失败或验证码连续错误时，任务进入“等待人工验证码”状态，Web 页面显示当前验证码。用户输入验证码后，程序使用钥匙串密码继续登录并恢复原任务。密码错误、钥匙串无密码或异地登录进入“需要人工处理”状态。

## 轮次识别

- 轮次解析结果包含 `id` 和页面可见名称；链接文字无法解析时名称退化为 ID。
- 程序选择轮次列表第一项作为当前轮次。
- 匹配到轮次后把轮次 ID 和名称写入运行状态，不把临时 ID 回写成用户关键字。
- 运行期间每轮课程扫描前重新获取轮次。所选轮次 ID 变化时立即进入新轮次并清除模块进入缓存。
- 启动或运行时轮次列表为空，任务保持运行并停止向旧轮次发送课程请求；每秒重新查询轮次列表。轮次恢复后选择第一项、重新进入轮次并继续所有未完成目标。

## 启动与持续运行

- 用户点击“开始抢课”后立即创建后台任务。
- 选定当前轮次后立即运行课程循环。
- 目标未成功时不因运行时长或单次提交失败自动结束，只有用户停止或进程关闭才会结束。
- 运行参数固定为每秒 5 次请求和 0.1 秒扫描间隔。

## 课程目标

### 搜索模式

搜索目标支持模块、课程名称、课程号、教师姓名、星期、节次、实验分组、优先级和互斥组。调度器使用现有课程搜索接口，并要求结果唯一；无结果、已满或冲突继续轮询，多结果保持失败状态并要求用户补充条件。

### 课程编号模式

课程编号目标只要求模块和课程编号 `kch`。程序每轮使用编号查询教学班，过滤冲突、本人已选和余量为零的记录；普通教学班逐个提交，讲课与实验行按父教学班关系自动配对后提交。

从课程目录添加的目标仍属于搜索模式并保存可靠标识。课程编号模式作为独立入口，不要求用户查找内部课程 ID 或教学班 ID。

## 互斥分组

- 目标可设置可选字符串 `exclusive_group`。
- 同一互斥组内任一目标完成提交并通过结果列表验证后，其余未完成目标立即标记为“同组已完成”并从待处理集合移除。
- 不同互斥组以及未设置分组的目标互不影响。
- 失败、已满、冲突或提交后未验证成功不会触发互斥跳过。

## 会话保活与恢复

- 等待开始阶段定期访问学生主页进行轻量保活。
- 正在抢课时，每个教务响应继续使用现有登录页和异地登录检测。
- 会话失效时暂停当前目标，自动登录成功后重新进入轮次和模块，并重试当前目标。
- 单次运行最多连续自动重登录三次；超过次数进入“需要人工处理”。
- 异地登录不循环争抢会话，直接停止并提示用户处理。

## Web 界面

- “自动化设置”只显示学号、密码保存状态、OCR 尝试次数和保活间隔。
- 页面说明内置 OCR 随控制台启动，并保留人工验证码回退。
- 密码使用独立的“保存到钥匙串”和“从钥匙串删除”操作。
- 顶部状态显示登录状态、选中轮次和固定请求速率。
- 目标课程支持搜索模式、高级模式、优先级与互斥组；课程目录添加仍是默认入口。
- 任务事件明确显示自动登录、OCR 重试、轮次变化、保活、重登录和互斥跳过。
- 配置保存后显示磁盘同步状态和最后保存时间。

## 组件边界

- `config.py`：配置模型、`config.json` 原子读写、权限和版本校验。
- `keychain.py`：macOS 钥匙串读写，不接触 Web 状态。
- `ocr.py`：内置 OCR 模型的单次初始化和非阻塞识别。
- `auth.py`：验证码、凭证编码、登录和会话验证。
- `rounds.py`：轮次名称解析与关键字选择。
- `automation.py`：自动登录、定时等待、保活和恢复编排。
- `scheduler.py`：课程循环、高级目标和互斥组状态转换。
- `app.py`：本地 API、错误映射和服务装配。

## 错误处理

- 配置文件损坏时不覆盖原文件；页面显示错误并允许下载或修复。
- 钥匙串命令失败、密码不存在和系统拒绝访问时显示明确错误。
- 内置 OCR 初始化失败、识别为空或验证码无效时按配置次数重试，然后转人工验证码。
- 找不到当前轮次或高级目标字段不完整时在启动前拒绝任务。
- `429` 和服务器错误继续使用现有退避；会话类错误走恢复流程。

## 测试

- 配置：默认生成、`0600` 权限、原子保存、损坏文件保护和敏感字段拒绝。
- 钥匙串：使用命令执行器替身测试保存、读取、删除和错误映射，不操作真实钥匙串。
- 登录：OCR 成功、验证码重试、人工回退、同源重定向和会话检查。
- 轮次：名称解析、关键字优先级、无匹配和多匹配。
- 自动化：立即启动、停止中断、当前轮次切换和保活重登录。
- 调度：搜索模式、高级模式、互斥组成功跳过和未验证不跳过。
- API 与 UI：配置保存、密码状态、自动任务状态、响应式布局和浏览器控制台。
- 所有网络测试使用 `httpx.MockTransport`，不连接教务系统、OCR 服务或真实账号。
