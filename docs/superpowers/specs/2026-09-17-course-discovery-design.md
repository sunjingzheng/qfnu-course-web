# 全部可选课程与加入监控设计

## 目标

用户登录后加载当前选课轮次下六个已支持模块的课程，查看完整课程信息，并自行从列表中添加需要监控的课程。用户不填写课程号、课程 ID 或教学班 ID。

## 操作流程

1. 用户登录教务系统。
2. 页面获取选课轮次。只有一个轮次时自动选择；存在多个轮次时由用户选择。
3. 用户点击“加载全部可选课”。
4. 服务端依次进入必修、选修、本学期计划、专业内跨年级、计划外和公选课模块并拉取课程。全部请求共用每秒 2 次的全局限速器。
5. 页面按模块展示返回的课程。用户可在本地按课程名、课程号或教师过滤，不会因筛选再请求教务系统。
6. 用户从课程行点击“添加到监控”。系统自动保存选课所需的课程和教学班标识。
7. 用户为需要的课程设置优先级，然后启动监控。

## 课程信息

每一行显示模块、课程号、课程名称、教师、学分、开课单位、课程类别、校区、上课时间、地点、容量、已选人数、剩余人数、冲突说明、教学班和实验分组。接口缺失的字段显示“未知”。

## 界面

- 命令栏移除“新增课程”。
- 工作区顶部增加课程目录工具栏，包含轮次选择、“加载全部可选课”、本地关键字筛选和模块筛选。
- 课程目录显示逐模块加载状态、总课程数和最后加载时间。
- 课程表的每一条可添加记录提供“添加到监控”按钮；已添加记录显示“已添加”。
- 目标课程表保留优先级编辑、刷新和删除。
- 未登录时加载按钮禁用。

## 后端接口

- `GET /api/rounds`：要求本地令牌和登录状态，返回轮次 ID。
- `POST /api/courses/catalog`：接收轮次 ID，依次进入六个模块并以空条件、大分页查询全部课程，返回按模块组织的课程记录和模块级错误。
- `POST /api/targets/from-candidate`：接收服务端最近一次目录中的候选索引和优先级。服务端从内存目录取记录并构造目标，避免信任浏览器提供的内部 ID。
- 目录只保存在当前进程内，退出登录时清空。

## 加入规则

- 普通课程保存模块、课程 ID、课程号、课程名、教学班 ID 和教师，后续精确匹配该教学班。
- 带实验学时的课程从实验分组行添加，保存课程和实验分组，不锁死实验教学班 ID，使调度器能重新匹配对应讲课班和实验班。
- 有实验分组的讲课行不允许直接添加，界面提示选择实验分组。
- 相同模块与教学班，或相同模块、课程与实验分组的目标不能重复添加。

## 不完整模块

接口文档记录部分模块在空关键字下可能返回空列表。服务端仍使用官方空条件查询并如实展示模块结果，不通过枚举关键字制造额外请求。模块返回空列表或失败时，页面单独显示该模块状态，其他模块结果仍可使用。

## 错误处理

- 未登录、轮次缺失、目录记录失效和重复目标返回明确提示。
- 单个模块失败不会丢弃已加载模块；响应包含模块错误。
- 会话失效、异地登录和限流沿用现有停止或退避策略。
- 重新加载目录替换旧目录，防止添加过期记录。

## 测试

- 单元测试覆盖扩展课程字段、六模块目录加载顺序、部分模块失败和候选转目标规则。
- 路由测试覆盖登录要求、轮次获取、目录加载和只接受内存候选索引。
- UI 合约测试覆盖课程目录控件、信息列和移除手工新增入口。
- Playwright 验证桌面和移动布局、课程添加流程及浏览器控制台。
